# VPN sign-in and authentication failures

Separate a network connection problem from an identity or authentication problem before routing. This article does not authorize an account reset or a change to VPN policy.

1. Confirm ordinary internet access and record the exact VPN client error without capturing secrets.
2. Ask whether the requester can sign in to another approved organization service.
3. If other services also reject sign-in, refer the case to identity support for verification.
4. If only VPN sign-in fails, provide the client version, profile name, and start time to authorized VPN support.
5. Have support check for a published service notice before asking for client changes.

Never ask the requester to send a password, MFA code, recovery code, or certificate. Account changes require authorized human review.
